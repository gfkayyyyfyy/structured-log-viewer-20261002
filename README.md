# 本地结构化日志查看器

建设面向开发者的本地日志分析产品，逐步覆盖 JSONL 与简单文本日志导入、级别和时间筛选、请求标识关联、统计摘要、文件轮转处理、错误记录定位和结果导出。

计划采用：Python 3 标准库 / json / re / sqlite3 / argparse。

## JSONL 日志查看器

按级别筛选一份本地 JSONL 日志，输出匹配行的行号和原始内容。仅使用 Python 3 标准库，无需网络或外部服务。

### 用法

```
python -m log_viewer <文件路径> --level <级别>... [--request-id <请求标识>] [--since <起始时间>] [--until <结束时间>] [--summary | --jsonl]
```

- `文件路径`：UTF-8 编码的 JSONL 日志文件（必需），支持 LF / CRLF 换行。
- `--level`：筛选级别（必需，至少提供一次），支持 `DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL`，忽略大小写及首尾空白，只做相等匹配。可重复提供以一次选择多个级别，记录的 `level` 等于任一所选级别即通过；不是严重程度阈值，重复选择同一级别不会增加输出，各选项的先后顺序也不改变输出顺序（始终按原文件行序）。提供一次时行为与单个级别完全一致。任一值为空字符串、全为空白或不受支持时视为参数错误（退出码 2，不读取文件），后续合法值不能覆盖该错误；完全缺少 `--level` 或某次缺值按参数解析错误处理。
- `--request-id`：可选的请求标识筛选。提供时仅输出顶层 `request_id` 字段与之**精确相等**的记录：区分大小写、不去除首尾空白、不做子串匹配。字段缺失、为 `null` 或非字符串仅视为不匹配，不产生警告。值不能为空字符串或全为空白。不传时不影响按级别的筛选结果。
- `--since`：可选的起始时间筛选，格式为 `YYYY-MM-DDTHH:MM:SSZ`（UTC，含起点；年份四位且非零，其余数字部分两位，日期与时分秒须有效；不接受小数秒、时区偏移、闰秒、小写分隔字母或首尾空白）。提供时仅输出顶层 `timestamp` 不早于该时刻的记录，与级别、请求标识条件同时满足才输出。启用后所有可解析为对象且 `level` 合法的非空记录都检查 `timestamp`：字段缺失、为 `null`、非字符串或格式非法时产生一条含行号的“无效日志：timestamp 缺失或格式无效”警告并跳过该行，不影响退出码。缺值、空值或格式非法时视为参数错误（退出码 2，不读取文件）。不传时完全不检查 `timestamp`。
- `--until`：可选的结束时间筛选，格式与 `--since` 相同（UTC，不含终点；仅输出顶层 `timestamp` **严格早于**该时刻的记录）。与 `--since` 同时给出时构成含起点、不含终点的区间，与级别、请求标识条件同时满足才输出。只给结束时间同样启用时间戳检查，检查规则、警告文案与行号约定与 `--since` 一致；JSON 损坏、顶层非对象及级别无效沿用原有警告，不叠加时间戳警告。缺值、空值或格式非法，或合法的 `--since` 晚于 `--until` 时视为参数错误（退出码 2，标准输出为空，不读取文件）；起止相等是合法的空区间，仍会检查无效记录。不传时行为与原来一致。
- `--summary`：可选的统计摘要开关，不带值。启用后不输出匹配行，标准输出只写一个 JSON 对象和末尾换行，包含三个字段：`matched_count`（同时满足全部筛选条件的记录数）、`invalid_count`（本次产生警告的无效行数，空白行不计入）、`by_level`（`DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL` 五个大写级别名称各自的命中数，未命中为零；各级别计数之和等于 `matched_count`）。级别按既有规则规范化（忽略大小写及首尾空白），重复选择同一级别不重复计数。警告仍按原行号和顺序写到标准错误；启用时间筛选后，未命中其他条件但时间戳无效的记录仍产生警告并计入 `invalid_count`。空文件、无匹配或合法空时间区间也输出完整摘要，退出码为 0。不传时保持逐行输出 `行号<Tab>原始行` 的既有行为不变。
- `--jsonl`：可选的 JSONL 导出开关，不带值，不能与 `--summary` 同时使用（同时出现时在读取文件前拒绝，标准输出为空，标准错误说明两者不能同时使用，退出码为 2）。启用后每条匹配记录只向标准输出写原始正文和一个末尾换行：取消 `行号<Tab>` 前缀，不加外层数组或统计字段。正文不重新序列化，首尾空白、字段顺序、中文及 JSON 转义保持原样；输入行分隔符按既有规则去除，正文中的单独 CR、U+2028 和 U+2029 原样保留；末行即使源文件没有换行也完整输出并补末尾换行。所有筛选条件（级别、`--request-id`、`--since`/`--until`）仍按原有语义组合，重复级别不重复输出，结果保持原文件行序。无效行仍只在标准错误产生含原始行号的警告，每行最多一条，不进入导出结果；空文件或无匹配时标准输出为空；正常完成（含存在无效行）退出码为 0。适合重定向到文件后经同一入口再次导入：`python -m log_viewer demo.jsonl --level ERROR --jsonl > result.jsonl`。

每个非空行应是含字符串 `level` 字段的 JSON 对象。行号从 1 开始按物理行计算；空白行跳过；无法解析或级别无效的行会在标准错误输出一条含行号的“无效日志”警告，不影响退出码。

匹配结果按原文件顺序写到标准输出，格式为 `行号<Tab>原始行`。正常完成退出码为 0（含无匹配、存在无效行的情况）；参数问题或文件读取失败（路径不存在、是目录、无法读取、非合法 UTF-8）输出错误信息并以退出码 2 结束。

### 示例

仓库自带 `sample.jsonl`：

```
$ python -m log_viewer sample.jsonl --level ERROR
第 3 行：无效日志：JSON 解析失败   （标准错误）
4	{"level":" error ","message":"失败"}   （标准输出）
```
